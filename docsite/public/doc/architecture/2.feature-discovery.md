# Feature-Based Discovery

Agent Smith uses a filesystem-based feature discovery system. Features are defined as YAML, JavaScript, or markdown files in user directories, discovered by scanning subdirectories, and registered into SQLite for fast lookup.

## Feature Types

The framework recognizes six feature types, each with specific file extensions:

| Type | Extension | Description |
|------|-----------|-------------|
| `agent` | `.yml` | YAML agent definitions with prompts, models, and variables |
| `action` | `.yml`, `.js`, `.py` | Action scripts — shell commands, JS ESM modules, or Python scripts |
| `workflow` | `.yml` | Workflow pipelines composed of sequential action steps |
| `adaptater` | `.js` | Data adapters for transforming inputs/outputs between systems |
| `cmd` | `.js` | Commander.js CLI command definitions |
| `skill` | `.md` | Markdown documentation files with front-matter metadata |

## Directory Structure

Features are organized in subdirectories within a feature root:

```
features/
├── actions/      # .yml, .js, .py files
├── agents/       # .yml files
├── workflows/    # .yml files
├── adaptaters/   # .js files
├── cmds/         # .js files
└── skills/       # directories with SKILL.md
```

Each subdirectory is scanned for files matching the expected extensions. For skills, each subdirectory must contain a `SKILL.md` file with front-matter containing `name` and `description` attributes.

## Discovery Mechanism

The discovery process is implemented in `@agent-smith/core`:

1. **Read feature paths**: The system reads registered feature directories from the `featurespath` table in SQLite.
2. **Scan directories**: For each registered path, it calls `readFeaturesDir()` which scans the six subdirectories for matching files.
3. **Parse metadata**: Files are parsed — YAML agents/workflows extract variables and structure; skills read front-matter; JS/Python actions parse tool documentation.
4. **Register in DB**: Discovered features are upserted into their respective tables (`agent`, `action`, `workflow`, `adaptater`, `cmd`, `skill`) using `upsertAndCleanFeatures()`.
5. **Create tools**: For agents, actions, and workflows with executable code, a `ToolSpec` is extracted and registered in the `tool` table.
6. **Update aliases**: Feature names are registered in the `aliases` table for command-line lookup.

## Running Discovery

To register new or updated features, run:

```bash
lm update
```

This triggers the `updateFeaturesCmd()` function from `@agent-smith/core`, which:
- Reads all registered feature paths (user directories + installed plugins)
- Scans each path for feature files
- Upserts discovered features into SQLite
- Cleans up entries for removed features
- Updates tool definitions and aliases

## Feature Specs

Each discovered feature produces a `FeatureSpec` object:

```typescript
interface FeatureSpec {
    name: string;
    path: string;
    ext: FeatureExtension;
    variables?: Record<string, any>;
}
```

The `FeatureType` union type is: `'agent' | 'action' | 'workflow' | 'adaptater' | 'cmd' | 'skill'`.

Features can also be loaded from npm plugins, which are registered in the `plugin` table and scanned during discovery.
