# Quickstart

Get up and running with Agent Smith in minutes. This guide walks you through installing the CLI, configuring your environment, creating a custom agent with tools, and running it.

## Step 1: Install

Install the Agent Smith terminal client globally:

```bash
npm i -g @agent-smith/cli
```

A global `lm` command is available once installed. Verify the installation:

```bash
lm --version
```

## Step 2: Install the Shell Plugin

The shell plugin provides sandboxed shell and Python execution tools for your agents:

```bash
npm i -g @agent-smith/feat-shell
```

This gives you access to the `shell` tool (execute commands in an isolated Docker container) and the `python` tool (run Python code in a container).

## Step 3: Create Your Features Directory

Create a directory structure for your custom features. This is where you'll define your agents, actions, workflows, and commands:

```bash
mkdir -p ~/my-agents/features/agents
mkdir -p ~/my-agents/features/actions
```

The `agents/` subdirectory holds agent YAML definitions. The `actions/` subdirectory holds tool scripts (`.js`, `.py`, or `.yml` files).

## Step 4: Create a Config File

Create a config file at `~/.config/agent-smith/config.yml`:

```bash
mkdir -p ~/.config/agent-smith
```

Then create the config file with your backend, features directory, and plugins:

```yaml
# ~/.config/agent-smith/config.yml

backends:
  default: "ollama"
  ollama:
    type: "openai"
    url: "http://localhost:11434/v1"

features:
  - ~/my-agents/features

plugins:
  - "@agent-smith/feat-shell"
```

> **Note**: Adjust the backend URL to match your inference server. Agent Smith supports any OpenAI-compatible API (Ollama, llama.cpp, vLLM, OpenAI, etc.).

Sync the config into the SQLite database:

```bash
lm conf ~/.config/agent-smith/config.yml
```

## Step 5: Create an Agent

Create a YAML agent definition in your features directory. This agent will use the `shell` tool from the shell plugin to execute commands:

```yaml
# ~/my-agents/features/agents/shell-demo.yml

description: "A demo agent with shell tool access"
prompt: |-
    {prompt}
model: qwen4b
inferParams:
    min_p: 0
    top_k: 20
    top_p: 0.95
    temperature: 0.4
toolsList:
  - shell
```

Key fields explained:

| Field | Purpose |
|-------|---------|
| `description` | Human-readable description of what the agent does |
| `prompt` | The prompt template — `{prompt}` is replaced with user input |
| `model` | The model to use for inference |
| `inferParams` | Sampling parameters (temperature, top_k, etc.) |
| `toolsList` | List of tools the agent can call — here we reference `shell` from the installed plugin |

## Step 6: Register Features

Run the update command to discover and register your new agent:

```bash
lm update
```

This scans your features directory, parses the YAML definition, and registers the agent in the SQLite database.

Verify it was registered:

```bash
lm agents
```

You should see `shell-demo` in the list of available agents.

## Step 7: Run the Agent

Run your agent with a prompt:

```bash
lm shell-demo "List files in the current directory"
```

The agent will:

1. Process your prompt through the configured model
2. Call the `shell` tool to execute `ls` in a sandboxed container
3. Return the results along with the model's response
