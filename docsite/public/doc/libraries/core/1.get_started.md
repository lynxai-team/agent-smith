# Core Runtime Engine

The `@agent-smith/core` package is the runtime engine of Agent Smith. It provides SQLite-backed configuration management, filesystem-based feature discovery, a unified tool execution engine, and Model Context Protocol (MCP) client integration. All agents, actions, workflows, commands, adaptaters, and skills are discovered from the filesystem, registered in a local SQLite database, and executed through a unified `ToolSpec` interface.

## Installation

```bash
npm install @agent-smith/core
```

The package depends on `@agent-smith/types` for shared interfaces, `better-sqlite3` for the embedded database, `yaml` for parsing YAML feature definitions, and `@modelcontextprotocol/sdk` for MCP server integration.

## Basic Usage

Import the main exports from the package entry point:

```typescript
import { db, conf, state, executeAction, executeWorkflow, useAgentExecutor, McpClient } from "@agent-smith/core";

// Initialize the SQLite database and process configuration
await conf.updateConfCmd(["conf"]);

// Discover and register features from configured paths
await conf.updateFeaturesCmd({});

// Execute an action by name
const result = await executeAction("read", ["./file.txt"], {});

// Or run a workflow that chains multiple steps
const workflowResult = await executeWorkflow("my-workflow", ["arg1"], {});
```

The core package exposes five main namespaces:

- **`db`** — Database operations (init, read, write) wrapping `better-sqlite3`
- **`conf`** — Configuration loading from `config.yml`, feature path registration, and database updates
- **`state`** — Reactive state management using Vue's `ref`/`reactive` for backends, agent settings, and runtime flags
- **`executeAction`**, **`executeWorkflow`**, **`useAgentExecutor`**, **`executeAgent`** — Tool execution functions
- **`McpClient`** — MCP client class for connecting to external tool servers

## Core Architecture

The runtime follows a discovery-execution pattern:

1. Configuration is loaded from `~/.config/agent-smith/config.yml` (or platform equivalent)
2. Feature search paths are read from the config and registered in SQLite's `featurespath` table
3. The filesystem under each path is scanned for agents (`.yml`), actions (`.yml`, `.js`, `.py`), workflows (`.yml`), adaptaters (`.js`), commands (`.js`), and skills (`.md`)
4. Discovered features are inserted into their respective SQLite tables (`agent`, `action`, `workflow`, `adaptater`, `cmd`, `skill`) for fast lookup
5. Execution functions resolve features by name from the database, load the file, and run it
